## 1. 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│ 客户端（单一 App，Flutter 业务层 + 双平台原生管控插件）          │
│  ├── 学生模式：解锁/答题/激励/锁定态守护                        │
│  └── 家长模式：题库/配置/管控中心/会员/报告                     │
└───────────────┬─────────────────────────────────────────────┘
                │ HTTPS(TLS1.2+) + HMAC 签名
┌───────────────▼─────────────────────────────────────────────┐
│ 接入层：SLB/网关（限流、WAF、鉴权 JWT 校验、路由）               │
├─────────────────────────────────────────────────────────────┤
│ 服务层（模块化单体，预留拆分）：                                │
│  账号服务 │ 题库服务 │ 出题引擎 │ 判分服务 │ 管控服务            │
│  风控服务 │ 会员订单服务 │ 广告奖励服务 │ 消息推送 │ 运营BFF      │
├─────────────────────────────────────────────────────────────┤
│ 中间件：Redis(会话/幂等/心跳) │ MQ(事件解耦) │ XXL-Job(定时)    │
├─────────────────────────────────────────────────────────────┤
│ 数据层：MySQL8.0 主从(读写分离) │ OSS(题图/导出文件) │ ES(审计/日志检索,二期) │
└─────────────────────────────────────────────────────────────┘
外部依赖：微信开放平台(OAuth/支付) │ 支付宝 │ 广告平台(穿山甲/优量汇) │ 厂商推送 │ 内容审核 API │ NTP
```

**选型理由**：当前团队规模（3~4 人）不适合微服务全拆——采用**模块化单体**（单部署单元内按包/模块隔离，模块间只经接口调用），订单与判分模块预留独立拆分边界（数据库表已按服务域拆分 schema）。客户端采用 Flutter 保证双端业务一致性（PRD 要求 Android/iOS 同版本双角色），管控能力用平台原生插件实现。

## 2. 客户端架构

### 2.1 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 业务框架 | Flutter 3.x（Dart） | 双端 UI 与业务逻辑统一；状态管理 Riverpod |
| Android 原生 | Kotlin | Device Admin / Foreground Service / WorkManager / 自启动适配 |
| iOS 原生 | Swift | FamilyControls/DeviceActivity/ManagedSettings（iOS16+，可选增强，PRD 7.8）、UNUserNotification |
| 本地存储 | SQLite（业务缓存）+ MMKV（配置）+ Keystore/Keychain（密钥） | 作答暂存、离线题包 |
| 网络 | Dio + 拦截器（签名/重试/心跳） | 详见 2.4 |
| 推送 | 厂商通道聚合（华为/小米/OPPO/vivo/荣耀 + APNs） | 家长告警、扣费提醒 |

### 2.2 客户端模块划分

| 模块 | 职责 | 对应 PRD |
|------|------|----------|
| auth | 微信 OAuth/手机号登录、身份选择、设备绑定与配额提示 | FR-31~33、FR-37 |
| guard（学生模式守护） | 锁定态渲染、前台服务保活、强停自恢复、卸载防护、时间校准 | FR-13、FR-18 |
| quiz | 出题请求、答题页（防切屏/防截屏）、作答暂存与补传 | FR-07~12、FR-36 |
| control | 会话状态机、使用中倒计时、免锁时段、紧急呼叫通道 | FR-12、FR-17、9.2 |
| reward | 积分/勋章/打卡/兑换（学生端只读自己数据） | FR-19~23 |
| parent | 题库管理、DIY 配置、管控中心、报告、会员中心、设备管理 | FR-01~06、FR-08、FR-24~25、FR-37/38 |
| security | 家长密码、敏感操作二次确认、异常上报 | FR-35、FR-14 |

### 2.3 守护与管控实现（Android，核心技术点）

| 威胁（PRD T-xx） | 实现方案 |
|------------------|----------|
| T-01 卸载 | Device Admin（`DeviceAdminReceiver`）+ 卸载需家长密码校验（本地存密码哈希比对，服务端二次校验）；未激活时开机广播强提醒 |
| T-02 强停 | 前台 Service（常驻通知）+ `JobScheduler`/`WorkManager` 双通道拉起 + `START_STICKY`；被杀事件通过 `TaskRemovedCallback` 上报异常 |
| T-03 改时间 | 所有计时仅展示用途；会话到期由服务端时间戳 + 心跳校准（2.4）决定，本地钟差 >5 分钟触发告警事件 |
| T-04 篡改/重放 | 请求签名：`HMAC-SHA256(method+path+timestamp+nonce+bodyHash, sessionKey)`；nonce 入 Redis 去重（10 分钟窗口） |
| T-05 换设备 | 设备指纹（ANDROID_ID + 硬件特征混合哈希）；登录时服务端比对绑定表 |
| T-06 切屏作弊 | 答题页 `FLAG_SECURE`（防截屏录屏）+ `onPause` 计数暂停计时；作答耗时 <2s 标记异常快答上报 |
| 厂商杀后台 | 各厂商「自启动 + 后台运行 + 电池白名单」引导页（逐厂商适配，占端上工作量 ~40%，估算）；未授权 → 降级模式（FR-18） |

### 2.4 心跳与 fail-open 协议（对应 E-15、FR-37）

```
学生模式设备每 30s 上报心跳：{deviceId, sessionState, localTs, sig}
服务端响应：{serverTs, sessionDeadline, failOpenDeadline, quotaState}

规则：
1. 心跳成功 → 用 serverTs 校准本地基准偏移（只用于展示）；
2. 连续失联 > 2h（服务端可配置下发）→ 客户端本地进入「临时开放」，
   事件写本地队列，恢复联网后补报；期间紧急呼叫/联系家长入口可用；
3. 心跳同时用于设备「在线」判定（72h 活跃窗口，FR-37 配额口径）；
4. 断网宽限（≤72h，可配）：缓存题包加密下发（见 2.5），恢复后补判。
```

### 2.5 离线题包安全（FR-36）

- 下发结构：`{题目ID, 题干, 选项}` —— **不含答案/解析**；
- 加密：AES-256-GCM，会话密钥由服务端下发且与设备指纹绑定（Keychain/Keystore 存储校验），解密失败即销毁题包；
- 作答暂存同样加密，上传成功后本地立即删除。

## 3. 服务端架构

### 3.1 服务模块（模块化单体 → 预留拆分）

| 模块 | 职责 | 关键表 |
|------|------|--------|
| account | 微信 OAuth/手机号登录、家庭账号、身份、设备绑定与配额 | user, family, student_profile, device_bind |
| bank | 题库 CRUD、批量导入、分类、回收站、内置题库、内容审核回调 | question, category, recycle, audit_content |
| quiz-engine | 出题（年级匹配+能力值+权重+7天去重）、错题重练、离线题包 | quiz_task, quiz_item, ability_value |
| grading | 服务端唯一判分、异常快答判定、幂等 | quiz_task(判分字段), answer_record |
| control | 解锁会话状态机、免锁时段、紧急解锁、fail-open 状态 | unlock_session, session_event |
| risk | T-01~T-08 威胁检测、异常事件、家长告警推送 | risk_event, alarm |
| member-pay | 会员/订单/支付回调/补单/退款/对账/资损监控（资金三件套落点） | vip_order, refund, reconcile_diff, member |
| ad-reward | 广告回调验签、幂等发奖、单日上限 | ad_reward, free_time_account |
| notify | 厂商推送聚合、模板管理 | push_record |
| ops-bff | Web 后台聚合接口（见 Web 技术架构文档） | — |

### 3.2 技术栈

| 项 | 选型 | 理由 |
|----|------|------|
| 框架 | Spring Boot 3（Java 21） | 团队主流、生态成熟、事务与定时任务完善 |
| ORM | MyBatis-Plus | — |
| 缓存 | Redis 7（会话、nonce 去重、心跳在线窗口、配额计数、分布式锁） | — |

| 文件 | OSS + CDN（题图、Excel 导入导出） | — |

### 3.3 资金链路关键设计（PRD FR-28，三件套落点）

```
下单：POST /pay/order → 服务端算价（分）→ 生成业务单号 → 渠道预下单
回调：/pay/notify/wx|alipay → 验签 → 幂等发货
      幂等实现：vip_order.out_trade_no 唯一索引 + Redis SETNX(pay:{out_trade_no})
      → MQ 事务消息「发货」→ 会员延期（同幂等键）
补单：XXL-Job 每 5 分钟扫描「已支付未发货 >5min」→ 主动查单 → 补发货（同幂等键，天然防重）
对账：每日 T+1 拉渠道账单 → 逐单比对（状态/金额/我方有渠道无/渠道有我方无）
      → 差异入 reconcile_diff → 后台处置 → 3 工作日未处理升级告警
资损监控（4 类告警规则）：
  ① 同 out_trade_no 发货记录 >1 条  ② 金额 <=0 或超阈值
  ③ 已退款订单出现发货事件          ④ 对账差异单 >0 且超 24h
```

退款：后台审批流通过 → 调渠道退款（原路）→ 回调查询双通道 → 会员权益按剩余天数折算终止（SVIP/VIP 差价不参与计算，FR-25）。

### 3.4 广告奖励链路（FR-27）

广告 SDK 客户端回调 → 服务端二次校验平台签名（回调 ID + 时间戳验签）→ Redis 幂等（`ad:{callback_id}`）→ 单日计数（Redis INCR + 当日过期）→ 超 10 天/日拒绝 → 发放免费时长（free_time_account 追加流水）→ 家长端到账通知。学生端不集成任何广告 SDK 组件（构建变体隔离：`student` flavor 不含广告依赖，防止误集成）。

### 3.5 出题引擎（FR-07）

规则引擎实现（首版不引入 ML）：年级过滤 → 科目权重抽样（加权轮盘）→ 难度分层抽样（能力值 ±1 级 ≥70%）→ 7 天去重（Redis Bloom Filter：`bloom:quiz:{studentId}:{week}`）→ 错题重练配额（≤30%）。能力值为「难度加权正确率」，XXL-Job 每日增量重算，实时判分事件触发即时更新。

## 4. API 与安全规范

> 认证与权限的完整设计（JWT 结构/refresh 旋转与撤销/身份 scope/家长密码/实名核验/认证 API 清单）见**《学习解锁-认证与权限设计文档-v1.0.md》**，本节仅保留规范摘要。

| 项 | 规范 |
|----|------|
| 风格 | REST + JSON；统一响应 `{code, msg, data}`；业务错误码分段（1xxx 账号 / 2xxx 题库 / 3xxx 解锁 / 4xxx 支付 / 5xxx 后台） |
| 认证 | JWT（access 2h + refresh 30d）；学生/家长 scope 隔离，学生 token 无家长接口权限（FR-10 配置脱敏在 BFF 层强制） |
| 签名 | 全部写请求 HMAC 签名 + nonce 防重放（2.3）；支付/广告回调各自平台验签 |
| 敏感数据 | 手机号/实名 AES 加密存储、展示脱敏；日志禁明文 PII；作答与题包加密见 2.5 |
| 审计 | 家长敏感操作（紧急解锁/下线设备/特权指定）发风控事件并留痕 ≥90 天 |
| 限流 | 网关按 deviceId+IP 双维度限流；答题提交接口幂等（taskId 唯一） |

## 5. 核心数据模型（主要表，详设阶段补全字段）

```
family(家庭账号) 1—N student_profile(学生档案) 1—1 device_bind(管控设备)
student_profile 1—N quiz_task(解锁任务,含配置快照+判分结果+异常标记) 1—N answer_record
question(题目,含来源/分类/状态) N—1 category；question 1—N question_rev(修改记录)
member(会员状态/到期时间/档位) 1—N vip_order(订单,幂等键 out_trade_no)
free_time_account(免费时长账户) 1—N ad_reward(广告发奖流水)
point_account 1—N point_flow；medal / checkin_record
risk_event(T-xx 事件) / alarm(家长告警) / unlock_session(会话状态机)
audit_content(机审工单) —— 供 Web 后台使用
```

## 6. 部署与可观测

| 项 | 方案 |
|----|------|
| 部署 | 云主机/K8s：SLB → 网关(2 实例) → 应用(≥2 实例)；MySQL 主从半同步 + 每日全备 + binlog 增量；Redis 哨兵 |

## 7. 关键技术风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| 厂商 ROM 杀后台导致守护失效 | 高 | 逐厂商适配矩阵 + 5 真机日测 + 降级模式兜底（FR-18）+ fail-open 最终兜底（E-15） |
| 支付回调丢失/重复 | 中 | 双通道 + 幂等 + 补单 + 对账闭环（3.3） |
| 广告回调伪造 | 中 | 服务端二次验签 + 回调 ID 幂等 + 单日上限 |
| Flutter 与原生管控插件的状态一致性（锁屏时机） | 中 | 状态机唯一事实源在服务端，客户端为投影；原生插件仅执行指令 + 上报 |
| iOS FamilyControls 审核不确定性 | 中 | 特性开关灰度，提审前 TestFlight 验证；被拒则回退提醒级（7.8） |
| 判分服务单点 | 低 | 无状态多实例；Redis 故障时降级为「DB 唯一索引幂等」 |

## 8. 里程碑技术对齐（映射 App PRD 13.2）

- M1：账号服务（OAuth/身份/绑定）+ 题库 + 出题判分主链路 + 心跳协议 v1；
- M2：守护与防绕过全量（T-01~T-08）+ 风控事件 + 离线题包 + fail-open；
- M3：会员订单（支付/对账/资损）+ 广告奖励 + 设备配额 + 推送；与 Web 后台 WB3 联调；
- 灰度：红队演练（T-01~T-08 全用例）+ 5 真机兼容回归。
