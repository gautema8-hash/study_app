# 「学习解锁」App 开发执行计划

> 版本：v1.0 ｜ 日期：2026-11-04 ｜ 依据：App PRD v1.4 · App 技术架构 v1.0 · 认证与权限设计 v1.0 · 防破解安全方案 v1.0 · 上线前置准备清单 v1.0
> 周期：**开发 12 周 + 灰度 2 周 ≈ 14 周到全量**（估算）；团队：产品 0.5 人 / Android 1 人 / iOS 1 人（W5 起） / 后端 1.5 人 / 测试 0.5 人（估算）

## 1. 三条并行轨道总览

```
轨道A 商务合规（关键路径！第 1 周全部启动，多数与开发并行）
W1 ──────── W4 ──────── W8 ──────── W12 ──── W14
│ICP/教育App备案启动          │备案预计下证        │
│微信平台+双支付签约 ──→ 就绪 │广告平台(需已上架)→ │
│题库授权谈判 ──→ 签约 ──→ 内容导入                │
│法律文书起草 ──────→ 定稿                        │

轨道B 服务端开发
W1-2 脚手架+认证鉴权 → W3-4 题库+出题判分+心跳 → W5-8 风控+订单+广告
→ W9-10 设备配额+推送+对账 → W11 联调 → W12 安全加固

轨道C 客户端开发
W1-2 Flutter骨架+登录身份 → W3-4 答题链路 → W5-8 Android守护+防绕过(重点40%)
→ W5-8 iOS(提醒级+FamilyControls spike) → W9-10 会员中心+设备管理 → W11-12 加固+回归
```

**关键依赖提示**：广告平台要求 App 已上架（死锁）→ 广告免费通道走「先上架免费版、后开广告」四步上线（见 §6）。

## 5. 风险与缓冲

| 风险 | 触发信号 | 应对 |
|------|----------|------|
| 备案下证慢于预期 | W8 未下证 | 上线顺序切「官网 APK 分发先行」小规模种子测试（合规前提下） |
| 厂商守护适配超预期 | W6 单厂商未通过 | 该厂商单独延后，其余先灰度；守护逻辑做厂商特性开关 |
| iOS FamilyControls 被拒 | 提审反馈 | 回退提醒级方案（7.8 预案），不影响 Android 全量 |
| 支付签约拖期 | W6 未就绪 | M3 拆分：广告/配额先行，支付单独立项里程碑 |
| 人力不足 | 任意 | 优先级保 T-01~T-08 防绕过与支付链路，激励/报告可延至灰度后迭代 |

**Buffer**：W11~W12 中预留 ~30% 未排任务量作为整体缓冲；每里程碑延期超 1 周必须触发范围裁剪决策（砍 P1 保 P0）。

## 6. 上线执行（衔接《上线前置准备清单》§7 四步走）

```
Step1（W14）：商店上架免费版（自建题库 + 3 天试用 + 身份/守护全量）
Step2（+1 周）：内置题库授权内容灰度开放
Step3（+2 周）：Android 支付四档全量 + 后台资金模块启用
Step4（按 IAP 结论）：iOS 支付开放
每步观察 ≥1 周：解锁完成率 / 崩溃率 / 绕过率 / 支付成功率
```
