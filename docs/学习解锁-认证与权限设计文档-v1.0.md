## 1. 账号体系与身份模型

```
family_account(家庭账号, 主体=家长)
 ├── 实名核验记录(1 条, 支付/管控前置)
 ├── 家长密码(操作密码, 独立于登录凭证, FR-35)
 ├── N × student_profile(学生档案: 昵称/年级/能力值)
 │       └── 1 × device_bind(学生模式管控设备, SVIP 最多 3 档案/设备)
 └── N × parent_device_session(家长模式登录会话)
```

**关键原则**：
1. 一个微信号/手机号 = 一个家庭账号，学生不独立注册（未成年人不采集独立实名身份，仅家长实名）；
2. 「身份」是会话属性而非账号属性：同一账号在不同设备/不同选择下获得不同 scope 的 token；
3. 孩子设备进入家长功能 = 申请新 scope，必须家长密码（T-08），服务端签发临时家长 scope token（15 分钟有效）。

## 2. 登录方式与流程

### 2.1 微信授权登录（主路径，FR-31）

```
App → 拉起微信 SDK → 用户确认授权
    → App 获得临时 code → 服务端 /auth/wechat:
        1. code 换 access_token（微信 API）
        2. 获取 openid/unionid
        3. unionid 查 family_account：
           ├─ 存在 → 签发 token（进入身份选择/直达）
           └─ 不存在 → 创建家庭账号 → 引导补手机号 + 实名核验
    → 返回 access_token + refresh_token
安全点：code 一次性（微信侧保证）；服务端持有 appsecret（永不落端）；
       openid/unionid 仅存服务端；昵称头像可选授权（11.4-5 数据最小化）。
```

### 2.2 手机号验证码登录（备用路径）

- 短信验证码 6 位、5 分钟有效、单号 1 分钟 1 条 / 日 10 条限流；
- 验证通过后与同一 family_account 绑定（微信与手机号登录互通）；
- 验证码错误 5 次 → 图形验证码 → 再错 5 次 → 锁定 30 分钟。

### 2.3 学生模式登录（孩子设备）

孩子设备不直接输账号密码：家长在已登录的家长设备上「添加学生设备」→ 生成一次性绑定码（10 分钟有效）→ 孩子设备输入绑定码完成学生模式登录并绑定设备。**此设计防止学生知道家长账号凭证后自行登录家长模式**（配合 T-08 双保险）。

## 3. Token 设计（App 端）

### 3.1 JWT 结构

```json
{
  "sub": "family:{familyId}",
  "scope": "parent | student",
  "profile": "studentId（学生 scope 时必填）",
  "device": "deviceBindId",
  "ver": "凭证版本号（用于全局撤销）",
  "iat": 1730724000, "exp": 1730731200
}
```

| 项 | 规格 | 说明 |
|----|------|------|
| access_token | 2h | 每请求携带；scope 决定可访问接口域 |
| refresh_token | 30 天 | 旋转使用：每次刷新作废旧 refresh（Redis 标记），检测到旧 refresh 复用 → 视为泄露，撤销该账号全部会话并告警 |
| 签名 | RS256 | 私钥仅认证服务持有，其他服务公钥验签 |
| 撤销 | 双通道：Redis 黑名单（单 token）+ `ver` 版本号（改密码/下线设备时 ver+1，旧 token 全部失效） |

### 3.2 会话与设备联动

| 场景 | 规则 | 对应 PRD |
|------|------|----------|
| 学生模式互踢 | 同一 student_profile 第二台设备登录学生模式 → 旧会话立即失效 + 家长告警 | FR-34 |
| 设备配额 | 登录时校验在线设备数（72h 心跳窗口）→ 超限返回 40301 + 在线设备列表 | FR-37 |
| 换绑 | 学生模式换绑 = 旧设备会话撤销（ver+1）+ 新设备绑定码激活 | FR-33、E-16 |
| 离线宽限 | 学生设备断网 ≤72h：本地缓存校验会话有效（离线题包正常），恢复后补同步 | FR-34 |
| 会员到期 | 不影响登录态，仅管控功能按 FR-30 暂停 | FR-30 |

### 3.3 App 端权限矩阵（接口 scope）

| 接口域 | parent scope | student scope | 临时家长 scope（15min） |
|--------|--------------|---------------|--------------------------|
| 题库/配置读写 | ✅ | ❌（配置接口仅返回脱敏状态，FR-10） | ✅ |
| 管控操作（紧急解锁/下线/收回） | ✅ + 家长密码 | ❌ | ✅ |
| 答题/激励/兑换 | ❌ | ✅ | ❌ |
| 报告 | 全量 | 仅本人简要版 | 全量 |
| 支付/会员 | ✅ + 实名核验 | ❌（不渲染入口） | ✅ |

服务端网关层按 scope 强制路由校验；学生 token 携带的 `profile` 必须与设备绑定关系一致（防改包换档案）。

## 4. 家长密码（操作密码）与登录凭证的关系（FR-35）

| 维度 | 登录凭证 | 家长密码（操作密码） |
|------|----------|----------------------|
| 用途 | 登录 App | 敏感操作二次确认：紧急解锁、设备下线/解绑、远程收回、孩子设备进家长功能、敏感兑换 |
| 形态 | 微信/短信登录（无独立密码） | 6 位数字 |
| 存储 | — | 服务端 bcrypt 哈希；孩子设备只存「是否已验证」标记，**不存密码** |
| 找回 | 手机号验证码 | 仅注册手机号验证码（FR-16）或后台客服核验重置 |
| 失败策略 | 验证码通道限流 | 错 5 次锁 30 分钟 + 告警家长主设备（T-08） |

## 5. 实名核验（监护人授权链路）

```
首次进入家长功能/支付前 → 实名核验页
→ 手机号运营方要素核验（三要素 API：姓名+身份证+手机号，一致性核验）
→ 通过 → family_account.kyc_status = VERIFIED → 监护人授权书签署留痕
失败 3 次 → 转人工客服通道（后台工单）
注：核验结果只存「已核验状态 + 核验时间」，身份证号加密存储、不回显
```

## 6. Web 后台认证（对《后台技术架构》§3.1 的补充细节）

- 会话：服务端 Session（Redis），HttpOnly + Secure + SameSite=Strict Cookie；闲置 30 分钟过期，绝对有效期 12h；
- 2FA：TOTP 绑定后不可跳过；「查看明文」等敏感操作要求**实时动态码**再验证（签发 5 分钟一次性许可，FR-W04）；
- 密码：12 位混合、90 天轮换、最近 5 组不可复用、bcrypt(cost≥12)；
- 登录审计：成功/失败全记录（IP/UA/时间），异地 IP 告警管理员；
- RBAC：权限点粒度到按钮/接口（`order:refund:approve` 格式），前端 access.ts 与后端网关双侧校验，后端为准（FR-W02）。

## 8. 安全事件与应急

| 事件 | 响应 |
|------|------|
| refresh_token 复用（疑似泄露） | 撤销该账号全部会话（ver+1）+ 强制重新登录 + 安全告警 |
| 家长密码疑似被破解 | 锁定操作密码通道，保留登录态但敏感操作全部冻结，短信通知家长 |
| 学生设备丢失 | 家长远程下线 + 解绑（家长密码）→ 丢失设备学生模式自动失效 |
| 后台账号疑似被盗 | 管理员停用账号 + 审计日志回查（哈希链校验该账号近期操作） |
| 微信授权关系异常 | 解绑流程需手机号验证码 + 实名状态复核 |

## 9. 里程碑与测试要点

- M1 交付：微信/短信登录、token 体系、身份选择、绑定码、家长密码；
- 测试要点：refresh 旋转与复用检测、ver 撤销全覆盖、学生 token 越权访问家长接口（应 403）、临时家长 scope 15 分钟过期、绑定码一次性、TOTP 时钟漂移容差（±1 窗口）。
