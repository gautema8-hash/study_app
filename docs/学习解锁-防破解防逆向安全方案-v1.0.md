# 「学习解锁」防破解与防逆向安全方案

> 版本：v1.0 ｜ 日期：2026-11-04
> 适用范围：学生端/家长端 App（Android/iOS）、Web 管理后台、服务端接口
> 核心理念：**客户端零信任**——所有判分、配额、会话、权益的最终裁决都在服务端；客户端防护的目标是把破解成本抬高到「不如直接用真实学习换取权益」的程度，而非追求绝对不可破解。
> 对应需求：App PRD v1.4 威胁模型 T-01~T-08、防绕过章节；技术架构文档。
> 合规声明：本方案为技术设计参考，具体实施请结合公司合规与法务要求确认。

## 2. App 端防护（Android）

### 2.1 代码与包体保护（对抗 A-01/A-04）

| 措施 | 实现 | 说明 |
|------|------|------|
| Dart 混淆 | `flutter build apk --obfuscate --split-debug-info=…` | 符号剥离，逆向 Dart snapshot 成本显著上升；debug-info 文件保密留存（用于还原崩溃堆栈） |
| Android 混淆 | R8 全量开启（minify + shrinkResources + optimization） | 自定义混淆字典 |
| 厂商加固 | 免费档：360 加固/腾讯乐固；商业档（推荐上线后评估）：梆梆/爱加密（含 Native VMP） | **必须验证与 Device Admin + 前台守护服务的兼容性**（加固壳可能影响拉起与广播接收，列入 5 真机回归项） |
| 签名保护 | v2/v3 签名方案；运行时校验 APK 签名摘要（多点校验：Java 层 + Native 层交叉） | 校验失败 → 上报风控事件 + 静默降级（不弹窗，防攻击者定位校验点） |
| Native 关键逻辑 | 签名校验/反调试检测放入 C/C++ so（OLLVM 混淆） | 抬高 hook 定位成本 |

### 2.2 运行环境检测（对抗 A-02/A-06/A-07）

检测到异常环境时执行**分级响应**：风险分累计 → 触发风控事件上报（服务端裁决）→ 高风险任务判分作废。**默认不本地阻断**（防误杀家长 root 机引发客诉），阻断决策在服务端。

| 检测项 | 手段（多点冗余，防单点被 hook） |
|--------|--------------------------------|
| Root | su 二进制路径扫描、Magisk 特征（挂载点/包名）、SELinux 状态 |
| Frida/Xposed | 27042 等默认端口、进程名扫描、/proc/self/maps 中 frida-gadget/xposed 特征 so、D-Bus 探测、inline hook 特征字节 |
| 调试器 | `ApplicationInfo.FLAG_DEBUGGABLE` 校验 + `ptrace(PT_TRACEME)`（native） |
| 模拟器 | 硬件特征（build 指纹/传感器缺失/电池状态恒定/IMEI 规律性）多因子打分，不单点判定 |
| 多开/分身 | 应用列表特征包名（VirtualApp 系）、私有目录路径异常、共享 UID 冲突检测 |
| 时间篡改 | 与心跳校准偏移 >5 分钟（PRD T-03/07，风控事件） |

### 2.3 通信安全（对抗 A-03）

1. **SSL Pinning**：Dio 层证书锁定（内置服务端证书公钥哈希，双证书预置支持轮换）；`networkSecurityConfig` 不信任用户 CA；
2. **业务层响应签名**（比纯防抓包更根本）：服务端对关键响应（判分结果/会话到期时间/配额）附加 `HMAC(body)`，客户端校验——即使抓包也无法伪造服务端指令；
3. **请求签名 + 防重放**：`HMAC-SHA256(method+path+ts+nonce+bodyHash, sessionKey)`，nonce Redis 去重 10 分钟窗口（已含于技术架构）；
4. 抓包兜底认知：PINNING 可被 Frida 绕过——因此**判分、积分、配额、会员状态全部服务端裁决，响应签名只是抬高成本**，抓包改包提交的作答在服务端风控（异常快答/切屏/耗时分布）面前无效。

### 2.4 数据与密钥保护（对抗 A-05/A-09）

| 项 | 方案 |
|----|------|
| 密钥管理 | 客户端**禁止硬编码任何 secret**；会话密钥登录后服务端下发且与设备指纹绑定；HMAC 密钥存 Android Keystore（StrongBox 优先）非导出区 |
| 本地库 | SQLCipher 加密作答缓存；MMKV 加密配置；离线题包 AES-256-GCM（无答案，FR-36） |
| 防备份 | `allowBackup=false` + `FLAG_SECURE`（答题页防截屏） |
| 数值零落地 | 倒计时/分数/积分/到期时间仅作展示投影，内存改了无意义（服务端为准，天然免疫 A-05） |
| 日志 | Release 关闭全部 verbose 日志；禁止打印 token/作答内容 |

### 2.5 设备指纹与脚本对抗（对抗 A-06/A-08）

- 指纹因子：硬件特征 + ANDROID_ID + 首次激活生成的服务端 UUID（持久化 Keychain/Keystore），**混合哈希**，单因子变化不触发换绑（避免误伤），多因子突变 → 换绑需家长扫码（PRD T-05）；
- 接口风控：网关按 device+IP 双维限流；答题提交行为序列风控（作答节奏熵值、切屏次数、异常快答）；批量注册识别（同设备簇/同 IP 段注册 → 风控人工审核）；
- 关键接口（支付下单/广告发奖/判分提交）增加设备完整性评分，低分设备要求滑块验证码升级。

## 3. App 端防护（iOS）

| 措施 | 说明 |
|------|------|
| 越狱检测 | /Applications/Cydia 等特征路径、可疑 dyld 注入、沙盒写测试；分级响应同 Android（上报为主） |
| 反调试 | `ptrace(PT_DENY_ATTACH)` + `sysctl` 检测 P_TRACED flag |
| SSL Pinning | URLSession/Alamofire 证书锁定；ATS 全量开启 |
| 防截屏 | 答题页隐藏屏显（`UITextField isSecureTextEntry` 技巧）+ 截屏监听上报 |
| 数据保护 | Keychain（kSecAttrAccessibleWhenUnlockedThisDeviceOnly）+ Core Data NSPersistentStoreFileProtectionKey 完整保护等级 |
| 逆向成本说明 | Flutter AOT + Swift 混淆下 class-dump 基本失效；不做越狱源分发场景，iOS 破解分发成本天然高于 Android——重点投入 Android 即可 |

## 4. Web 管理后台防护（对抗 W-01~W-03、S-01）

| 层 | 措施 |
|----|------|
| 网络层 | 仅内网/VPN 可达 + IP 白名单 + WAF（云 WAF 基础版即可）；后台域名不对外解析 |
| 认证层 | 双因素 TOTP、12 位密码 90 天轮换、5 次锁定、异地登录告警（认证文档 §6） |
| 会话层 | HttpOnly + Secure + SameSite=Strict、闲置 30 分钟过期、绝对 12h、登录即换 Session ID（防固定） |
| 授权层 | RBAC 双侧校验（前端 access.ts + 后端网关，后端为准）；水平越权防护：资源归属校验（只能操作自己工单/审批单）；接口幂等键防重复提交 |
| 注入防护 | 全量参数化查询（MyBatis `#{}`，代码评审禁 `${}` 拼接）；XSS：富文本（工单回复）走白名单过滤；CSRF Token；SSRF：对账拉单等出站请求白名单域名 |
| 内部风险 | 敏感操作双人复核 + 审计哈希链（已设计）；明文查看二次验证；只读从库账号与写账号分离；离职即日回收账号（IAM 流程） |
| 供应链 | 依赖锁定 + 每周漏洞扫描（npm/maven）+ 私服镜像；脚手架只改业务层不动安全基线 |

> 内部后台前端代码混淆价值低（用户是员工），安全重心放在认证、授权与审计——这是与 C 端 App 防护思路的本质区别。

## 5. 服务端与密钥治理

| 项 | 方案 |
|----|------|
| 密钥管理 | appsecret/支付密钥/HMAC 主密钥存 KMS 或加密配置（Nacos 加密插件），禁止进 Git（pre-commit 扫描 + GitGuardian 类监控）；密钥轮换预案（双密钥并行窗口） |
| 环境隔离 | dev/staging/prod 独立账号体系与密钥；staging 禁连生产库 |
| 最小权限 | 数据库账号按模块分权（订单服务账号无题库表写权限）；OSS 签名 URL 短时效 |
| 接口防护 | 全局限流、验证码升级通道、批量注册风控（§2.5）；支付/广告回调平台验签 + 回调 ID 幂等 |
| 数据防拖库 | 敏感字段（手机号/实名）应用层加密（密钥在 KMS，DB 泄露不可解）；导出强制脱敏 + 审计（后台 FR-W06） |

## 6. 安全监控与响应

| 事件 | 检测 | 响应 |
|------|------|------|
| 破解版分发 | 上线后定期搜分发市场/网盘关键词「学习解锁 破解/无限时长」；App 内签名校验失败事件突增 | 风控：破解版设备指纹拉黑名单；法务：留存证据投诉下架 |
| 接口被脚本刷 | 单设备请求频率熵值异常、验证码通过率骤降 | 自动限流 + 设备评分降级 + 人工复核 |
| 广告奖励被刷 | 发奖量/设备异常（同设备高频回调、模拟器特征） | 冻结账户 + 风控工单（后台处置） |
| 后台异常操作 | 非工作时间敏感操作、批量导出、审批间隔异常 | 实时告警管理员 + 哈希链核查 |
| 安全事件应急 | —— | 24h 应急流程（PRD 11.3-8）：止损（封禁/下线开关）→ 溯源（审计链）→ 修复 → 复盘 |

## 7. 实施优先级与成本

| 阶段 | 措施 | 成本（估算） |
|------|------|--------------|
| M1~M2 必做 | Dart/R8 混淆、SSL Pinning、响应签名、请求签名防重放、运行环境检测（上报模式）、Keystore 密钥、SQLCipher、allowBackup=false | 纯开发量 ~1.5 人周 |

| 常态 | 红队演练随版本（T-01~T-08 + 本文档 A-01~A-09 用例）、依赖漏洞周扫描、密钥季度轮换 | 每版本 ~0.5 人天 |

## 8. 红队自测用例（每版本回归）

| # | 用例 | 预期 |
|---|------|------|
| RT-01 | jadx 反编译产物中搜索 secret/hmac/key | 无明文密钥 |
