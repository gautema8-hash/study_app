# 「学习解锁」Web 管理后台 执行计划

> 版本：v1.0 ｜ 日期：2026-11-04 ｜ 依据：Web 后台 PRD v1.0 · Web 技术架构 v1.0 · 认证与权限设计 v1.0 · 防破解安全方案 v1.0
> 周期：**开发 6 周（WB1~WB3）+ 灰度 1 周 ≈ 7 周**；团队：前端 1 人 / 后端 0.5 人（复用 App 后端人力，后台为主服务模块） / 测试 0.25 人（估算）
> 关键对齐：**WB2（资金处置）必须与 App M3（W9~W10）同步，WB3 全部完成不晚于 App 灰度开始（W13）**——否则退款/对账/审核无法闭环。
> 合规声明：本计划为执行参考，具体实施请结合公司实际资源确认。

## 1. 里程碑与出口标准（DoD）

| 里程碑 | 周 | 范围 | 出口标准 |
|--------|----|------|----------|

## 3. 依赖与对齐关系

| 依赖项 | 就绪时限 | 拖期应对 |

## 4. 风险与缓冲

| 风险 | 应对 |
|------|------|
| 前端 1 人带宽不足（App 端共用人力） | 后台 UI 全部采用 Pro 组件默认样式，禁止自定义视觉设计；优先保 WB2 |
| 审计哈希链性能（高频操作） | 敏感操作同步写、普通操作 MQ 异步（架构文档 §7 已定）；上线前压测 1000 ops/min |
| 对账规则边界（渠道账单格式差异） | W4 预留 2 天处理真实账单样例；微信/支付宝账单文档提前研读 |
| 双人复核流程缺第二人（小团队） | 明确审批人矩阵：财务↔运营互为复核人，禁止同人；管理员兜底 |

**缓冲**：WB3 内的看板美化、工单统计图等 P2 项为可裁剪项；硬性不可裁剪 = 审计/退款/对账/紧急下架。
