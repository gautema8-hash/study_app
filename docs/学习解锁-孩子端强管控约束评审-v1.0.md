# 孩子端「强管控」约束评审与确认结论

> 日期：2026-11-05 ｜ 范围：仅孩子端（学生模式），**家长端行为零改动**
> 输入约束：①应用运行期间不允许退出或切离（返回/桌面/切其他应用），始终锁定在应用内；②开机/重启后自动启动，无需手动打开；③启动后跳过首页、登录等中间步骤，直接进入答题环节。

## 一、逐条合理性判定

| 约束 | 判定 | 说明 |
|------|------|------|
| ① 不允许退出/切离 | **有条件合理** | 这是管控类产品标准的 Kiosk / LockTask 形态，方向正确；但 Android 普通应用无法拦截 HOME/最近任务，必须依赖 **Device Owner + LockTask 模式**；且必须保留安全例外，否则会与既有安全底线冲突（见 §2） |
| ② 开机自启 | **有条件合理** | Android 可用 `RECEIVE_BOOT_COMPLETED` + 前台服务实现；**小米 HyperOS 等国产 ROM 需手动授予「自启动」白名单**，纯代码无法保证；iOS 不支持（PRD 7.8 已定义为提醒级管控） |
| ③ 直达答题 | **需修订为「直达该进的状态」** | 若开机时已有「使用中」会话、处于免锁时段、今日挑战次数用尽、题库为空或后端不可达，一律强制重新答题会造成：会话被重置、重复刷积分/打卡、白屏锁死等漏洞。应由服务端统一裁决启动状态 |

## 二、与现有需求的冲突（必须处理，否则不可上线）

| 冲突项 | 来源 | 处理结论 |
|--------|------|----------|
| 紧急呼叫与联系家长必须永远可用 | FR-17（安全底线，不可妥协） | 锁任务白名单放行拨号/紧急呼叫；答题页保留「紧急呼叫」入口 |
| 服务端失联 2h 自动临时开放 | E-15 fail-open「宁可漏管，不可错锁」 | 开机直达逻辑必须先探测后端；不可达时进入临时开放态而非锁死 |
| 会员到期后学生手机恢复正常自由使用 | FR-30（未成年人权益优先于商业化） | 强管控仅在会员/试用/免费天数有效且服务端判定需管控时生效 |
| 家长紧急解锁 / 远程收回 | FR-15 | 必须保留家长远程指令可解除 kiosk |
| 免锁时段、每日挑战次数上限、会话有效期 | FR-08 | 直达逻辑必须服从这些规则，不能每次开机都重置 |
| 孩子设备切家长身份需家长密码 | T-08 / FR-32 | 家长管理入口不能因 kiosk 完全消失：保留「长按 + 家长密码」的唯一入口 |
| iOS 提醒级管控 | 7.8 平台强度表 | iOS 保持现状，不实现系统级锁定（系统能力限制） |
| 只管控 1 台手机 | 4.2 范围声明 | 开机自启/直达仅作用于已绑定的孩子设备；家长设备不受任何影响 |

## 三、遗漏项（本轮一并补齐设计）

1. **开机网络未就绪 / 后端不可达** → fail-open 状态页，而非白屏锁死；
2. **token 过期或被撤销（ver+1）** → 静默走重新绑定流程，孩子端不能卡死；
3. **来电、闹钟、系统权限弹窗** → 锁任务例外，不拦截；
4. **家长/客服如何退出 kiosk** → 家长密码长按入口 + 服务端远程收回；
5. **设备管理器/自启动授权由谁触发** → 确认：在**孩子设备首次绑定成功时**弹出一次性系统授权引导（属于孩子端初始化，家长端 UI 不改动）；未授权时降级为「提醒级」并显著标识，不阻断答题；
6. **离线场景** → 复用 FR-36 加密离线题包，开机无网也能出题、联网后补判；
7. **商店合规** → 设备管理员权限用途说明（RK-12 已知风险）与未成年人保护说明需随上架材料更新；
8. **关机长按电源 / 恢复出厂 / 安全模式** → 属于 PRD 已声明的范围外威胁，本轮不宣称覆盖。

## 四、确认版约束（本轮按此实现）

**C1 启动状态由服务端裁决，孩子端三态直达**：`quiz`（自动开始答题）/ `using`（使用中倒计时）/ `wait`（题库不足、次数用尽、免锁、会员到期、fail-open 等带原因提示）。跳过登录与首页，但遵守全部既有规则。

**C2 全锁定只在以下四个条件同时成立时启用**：① 服务端判定需管控；② 家长已激活设备管理员；③ 处于孩子模式；④ 未触发任何例外。例外白名单：紧急呼叫、来电、家长密码长按入口、fail-open、会员到期、家长远程收回、试用/免费天数到期。

**C3 开机自启**：BOOT_COMPLETED + 前台守护服务 + LockTask；未获 ROM 自启动授权时降级提醒级；**家长设备完全不注册此行为**（由本地 `childMode` 标记控制）。

**C4 家长端零改动**：登录页、身份选择家长分支、家长首页 DIY、会员、后台管理流程一律不动。

**C5 平台边界**：Android 实现系统级守护；iOS 保持提醒级管控（7.8 既有约定）。

## 五、真机验证结论与补救（2026-11-05 小米 15 / HyperOS 实测）

| 验证项 | 结果 |
|--------|------|
| 返回键不可退出 | ✅ `PopScope(canPop:false)` 生效，按返回后仍在本应用 |
| 开机广播拉起守护服务 | ✅ `BootReceiver` → `GuardService` 成功（dumpsys 可见 ServiceRecord） |
| 开机广播直接拉起 Activity | ⚠️ **被国产 ROM 后台启动 Activity 限制拦截**（5 秒后仍在系统桌面），`adb dpm set-device-owner` 在本机亦失败（账号/FRP 限制）→ 与 D-2 预判一致 |
| 直达答题（跳过首页/登录） | ✅ childMode 生效后启动直接由 gate 自动出题进入「答题 1/2」；题库不足时正确显示 E-03 等待家长配置（C1 修订版行为） |
| 一次性授权引导 | ✅ 系统「启用设备管理应用」弹窗正常，用途说明含「家长端不受影响」 |
| 家长端零改动 | ✅ 家长登录/身份选择/家长首页 DIY 均保持原样 |
| 冷启动直达（新 APK） | ✅ `am force-stop` 后冷启动，childMode 标记生效，直接由 gate 自动出题进入「答题 1/2」，无任何登录/首页中间步骤 |
| 动态 HOME 别名 | ✅ 仅孩子设备启用（dumpsys package 可见 `.KioskLauncher` HOME filter）；家长设备保持禁用 |
| 设为默认桌面 | ⚠️ `cmd package set-home-activity` 在 HyperOS 返回 `Failed to set default home`（系统限制），需家长在「设置 → 默认应用 → 桌面」手动选择一次；未设置前按 HOME 回系统桌面（提醒级降级，符合 D-2，不锁死） |

**补救实现**：新增**动态 Kiosk 桌面别名**（`activity-alias .KioskLauncher`，默认禁用）：
- 仅孩子设备由 `MainActivity.enableKiosk()` 动态启用；系统开机必然启动 HOME → 直接拉起孩子端（绕开「广播后台启动 Activity」限制），按 HOME 也回到孩子端；
- 例外态（fail-open / 会员到期 / 家长密码退出）自动禁用别名，恢复系统桌面；
- 首次启用后需家长在系统「默认桌面」选择器中确认一次（一次性授权，属于 D-2 已声明的设备授权结果依赖）；
- LockTask 模式仍保留，供真正成为 Device Owner 的设备（如恢复出厂后配置/企业下发）使用；未授权设备降级为「HOME 别名 + 前台守护」提醒级，绝不锁死。

## 六、对用户的待拍板项（不阻塞本轮实现，按上述默认执行）

- D-1：设备管理器授权时机 → 已按「孩子设备首次绑定时引导」实施；若希望改由家长端统一开通，需后续迭代（会触碰家长端，超出本轮范围）。
- D-2：真机小米 15 的 HyperOS 自启动白名单与 Device Owner 激活可能受系统限制，实际生效强度以设备授权结果为准；未授权不会锁死，只降级。
