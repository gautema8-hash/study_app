# 「学习解锁」Web 管理后台 技术架构文档

> 版本：v1.0 ｜ 日期：2026-11-04 ｜ 配套需求：《学习解锁Web管理后台-产品需求文档PRD v1.0》
> 定位：内部运营管理后台（Admin Console），与 App 端共用服务端（假设 W-01），本文档聚焦后台自身的前端、权限、审计与处置链路技术实现。
> 合规声明：本方案为技术设计参考，具体实施请结合公司合规与法务要求确认。

## 1. 架构总览

```
┌──────────────────────────────────────────────────────────┐
│ 浏览器（Chrome/Edge，内网/VPN 访问）                        │
│  React 18 + Ant Design Pro（RBAC 路由/组件级权限）          │
└──────────────┬───────────────────────────────────────────┘
               │ HTTPS
┌──────────────▼───────────────────────────────────────────┐
│ 权限网关（独立于 App 网关）                                 │
│  2FA(TOTP) 校验 │ 会话管理 │ IP 白名单 │ RBAC 鉴权 │ 审计埋点 │
├──────────────────────────────────────────────────────────┤
│ 运营 BFF 层（ops-bff 模块，聚合主服务域）                    │
│  用户管理 │ 订单退款 │ 对账处置 │ 题库运营 │ 审核工单          │
│  客服工单 │ 数据看板 │ 系统配置                              │
├──────────────────────────────────────────────────────────┤
│ 主服务域（与 App 端同一套模块化单体，见 App 技术架构文档 3.1） │
├──────────────────────────────────────────────────────────┤
│ 数据层：MySQL 主(业务写) + 从(报表只读) │ OSS(导出文件)      │
│        审计库(独立实例, append-only)                        │
└──────────────────────────────────────────────────────────┘
```

**选型理由**：后台 PRD 方案 B——基于成熟开源 Admin 脚手架二次开发。选用 **React + Ant Design Pro**（UMI）：RBAC 路由、ProTable/ProForm 覆盖 90% 列表与表单场景，团队只需实现业务逻辑与审计/审批等自建能力。

## 2. 前端架构

### 2.1 工程结构

```
admin-web/
├── config/            # UMI 配置、代理
├── src/
│   ├── access.ts      # 前端 RBAC：permissionCode → 路由/按钮可见性
│   ├── pages/
│   │   ├── workbench/     # W1 工作台（四类待办红点）
│   │   ├── user/          # W2 用户管理
│   │   ├── order/         # W3 订单与退款审批
│   │   ├── reconcile/     # W4 对账中心 + 资损告警
│   │   ├── bank/          # W5 题库运营（批量导入/上下架）
│   │   ├── review/        # W6 审核工单
│   │   ├── ticket/        # W7 客服工单
│   │   ├── dashboard/     # W8 数据看板
│   │   ├── setting/       # W9 系统配置（价格/试用/灰度/词库）
│   │   └── iam/           # W10 账号权限 + 审计日志检索
│   ├── components/    # 通用：双人复核弹窗、脱敏字段、明文查看(二次验证)
│   └── services/      # API 封装
```

### 2.2 前端关键机制

| 机制 | 实现 |
|------|------|
| RBAC | 登录后拉取 `permissionCodes`；路由守卫拦截 + 按钮级 `<Access>` 包裹；后端为最终裁判（越权 403 + 告警，FR-W02） |
| 敏感字段脱敏 | 统一 `<SensitiveText>` 组件：默认脱敏展示，「查看明文」需二次验证（TOTP 动态码）→ 后端签发 5 分钟明文查看许可并审计（FR-W04） |
| 双人复核 | 通用 `<DualReview>` 组件：发起 → 二次审批人（不可同人，服务端校验）→ 通过/驳回；用于退款、封禁、批量下架、价格配置（FR-W08/W18） |
| 异步导出 | 大导出走任务：提交 → MQ → OSS 生成 → 站内通知下载链接（7 天有效）；导出自动脱敏并审计（FR-W06） |
| 批量操作 | 前端分批（500/批）提交 + 影响范围预览弹窗（题库批量下架/导入，WK-02 对策） |

## 3. 后端（ops-bff）关键设计

### 3.1 账号与认证

> 认证与权限统一设计（含本节展开：TOTP 参数、会话、RBAC 权限点命名、安全事件应急）见**《学习解锁-认证与权限设计文档-v1.0.md》§6**，本节为摘要。

| 项 | 方案（FR-W01） |
|----|----------------|
| 账号 | 仅管理员创建，禁自助注册；密码策略（12 位混合 + 90 天轮换） |
| 2FA | TOTP（RFC 6238）：绑定后登录必须动态码；连续 5 次失败锁 30 分钟 |
| 会话 | 独立会话体系（与 App JWT 隔离）：Session + HttpOnly Cookie，闲置 30 分钟过期 |
| 网络 | 仅内网/VPN 可达 + 网关 IP 白名单；HTTPS 强制 |

### 3.2 审计日志（FR-W03，append-only）

```
审计表 audit_log（独立 MySQL 实例）：
id, operator_id, module, action, target_type, target_id,
before_json, after_json, ip, ua, created_at, prev_hash, self_hash

防篡改：哈希链 —— self_hash = SHA256(prev_hash + 业务字段序列化)
XXL-Job 每日校验链完整性，断链即高危告警；
审计库账号仅 INSERT/SELECT 权限（无 UPDATE/DELETE）；
保留 ≥3 年（资金操作按财务规范）。
```

实现方式：Spring AOP 注解 `@Audited(module, action)`，统一在 BFF 层织入；操作与审计写入同事务（WE-04：审计失败则操作回滚）。

### 3.3 退款审批流（FR-W08）

状态机：`申请 → 客服初审 → 财务复核 → 渠道退款中 → 已退款/已驳回`（每步可驳回留痕）。实现：工作流简化为 DB 状态机 + 乐观锁（不引入独立工作流引擎，节点数 ≤3 无必要）；双人复核由服务端校验审批人 ≠ 发起人。免审快速通道：月卡误扣 ≤¥9 且 72h 内申诉，财务单人处理（阈值走配置）。

### 3.4 对账与资损（FR-W09/W10）

```
XXL-Job 每日 02:00 拉取渠道 T-1 账单（微信/支付宝文件接口）
→ 标准化落表 reconcile_bill → 与 vip_order 逐单四方比对：
   ① 状态不一致 ② 金额不一致 ③ 我方有渠道无 ④ 渠道有我方无
→ 差异生成 reconcile_diff 单 → 处置（补单/冲正/标记）→ 关闭留痕
→ 3 工作日未处理自动升级（IM 告警至管理员）
资损告警（4 类规则同 App 技术架构文档 3.3）→ 实时 IM 推送 + 后台红点
```

### 3.5 数据看板（FR-W17）

- 报表查询全部路由到**只读从库**（注解 `@ReadOnly` + 动态数据源），超时 3s 熔断降级（WE-01，保护 App 主链路）；
- 指标层：每日凌晨预聚合到 `stat_daily` 宽表（指标口径与 App PRD 2.2/10.3 同源，同一计算服务，杜绝双口径）；看板页只查宽表 + 实时小表；
- 导出走异步任务（2.2）。

### 3.6 系统配置（FR-W18）

配置项（价格/试用天数/广告上限/灰度开关）统一存 `sys_config`，Nacos 下发至 App 服务端；价格类变更强制双人复核 + 全量审计；灰度开关支持按用户比例（hash 分桶）放量。

```

```

## 5. 非功能与部署

| 项 | 方案 |
|----|------|
| 部署 | 与主服务同 VPC 独立子网；2 实例（无状态）+ SLB（内网）；审计库独立实例 |
| 兼容 | Chrome/Edge 最近两个大版本；最小 1366×768 |
| 性能 | 列表 P95 ≤2s（ProTable 服务端分页 + 覆盖索引）；导出 1 万行 ≤30s（异步）；看板 P95 ≤3s（宽表） |
| 可用性 | 后台故障不影响 App 主链路：读写隔离 + 独立网关；后台可短时停机发布（业务低峰） |
| 备份 | 审计库每日备份且异地留存；主库同 App 端策略 |
| 安全基线 | 登录防爆破（验证码+锁定）、CSRF Token、CSP、依赖漏洞周扫描（Dependabot 类） |

## 7. 技术风险与对策

| 风险 | 对策 |
|------|------|
| 审计日志成为写路径性能瓶颈 | 异步缓冲 + 同事务失败回滚折衷：敏感操作（资金/权限）同步写，普通操作 MQ 异步写 + 每日对账补齐 |
| 哈希链校验在大数据量下变慢 | 按月分链 + 每月锚点快照存 OSS（含时间戳） |
| 后台慢查询冲击主库 | 只读从库 + 3s 熔断（3.5）；上线前全量 SQL Explain 评审 |
| 双人复核形同虚设（秒批） | 服务端强制审批间隔 ≥5 分钟 + 审批人 ≠ 发起人 + 审批行为审计 |
| 开源脚手架供应链风险 | 锁定版本 + 私服镜像 + 漏洞周扫描 |
